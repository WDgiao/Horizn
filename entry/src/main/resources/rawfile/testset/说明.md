# 补充测试素材说明

`rawfile/testset/` 下的素材针对的是开发中发现的具体薄弱点，
与 `rawfile/codec/` 那 12 个「每个格式一个」的格式覆盖样本性质不同。

应用内用法：设置页 → **「出测试集」** → 解包到沙箱的 `测试素材/` 目录 →
搜索页点「重新扫描」即可看到。

## 当前素材

| 文件 | 编码 | 尺寸 | 时长 | 音轨 | 体积 | 验证什么 |
|---|---|---|---|---|---|---|
| `长视频_rv20_10秒.rm` | rv20 | 160x120 | 10.03 秒 | ac3 | 176 KB | **seek 压测** |
| `无音轨_rv20.rm` | rv20 | 160x120 | 5 秒 | 无 | 66 KB | **时钟回退** |

### 为什么需要这两个

**`长视频_rv20_10秒.rm`** —— 原有的 `12_rv10.rm` 只有 2 秒，
seek 几乎没有可跳转的空间，导致 seek 路径一直没被有效压测过。
（曾经想用 RemuxLoop 把短片拼成长片，但那条路走不通：这份 FFmpeg 构建
装不了 RV10 到 Matroska，而 FFmpeg 本身没有 rm 复用器。）

**`无音轨_rv20.rm`** —— 验证「没有音频轨时是否退回单调时钟」。
有音频时视频跟着音频时钟走；如果没有音频轨还去读音频时钟，
时钟会停在 0，画面就会一直等 —— 表现为"打开后黑屏不动"。

## 生成命令（可复现）

```bash
# 长视频：rv20 + ac3，10 秒
ffmpeg -f lavfi -i "testsrc2=size=160x120:rate=12:duration=10" \
       -f lavfi -i "sine=frequency=440:sample_rate=22050:duration=10" \
       -c:v rv20 -q:v 12 -c:a ac3 -b:a 32k -f rm 长视频_rv20_10秒.rm

# 无音轨：rv20，5 秒（-an 不要音频）
ffmpeg -f lavfi -i "testsrc2=size=160x120:rate=12:duration=5" \
       -an -c:v rv20 -q:v 12 -f rm 无音轨_rv20.rm
```

生成后**必须用 ffprobe 验证**（只看得文件生成是不够的）：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height -show_entries format=duration 文件
```

## 造不出来但很需要的素材

### ⚠️ 真正的 `.rmvb`（RV40 + Cook）

**无法自制。** FFmpeg **从来没有 `rv30`/`rv40` 编码器**
（RealVideo 8/9/10 的编码器实现从未公开），`cook` 音频编码器也没有。
FFmpeg 里有 `rv30`/`rv40` 的**解码器**（这正是内置软解的价值），但没有编码器。

所以 `.rmvb` 的真实播放能力**只能靠真实样本验证** ——
从网上找一个 RMVB 文件，或把老设备里的视频导出来。
这是当前最大的验证缺口：RMVB 才是 RealMedia 的主流格式，
而 `rv10`/`rv20`（能造出来的）是早期版本，代表性不足。

### ⚠️ 带旋转元数据的视频（竖拍）

**未能造出。** 尝试过三种方式都失败：

| 方式 | 结果 |
|---|---|
| `-metadata:s:v rotate=90` | FFmpeg 8 已移除该写法，元数据没写进去 |
| `-display_rotation 90`（输入侧） | 对 lavfi 输入不生效（lavfi 没有矩阵可改） |
| 先编码再 remux 加元数据 | 同上 |

**能用的工具手边没有**：系统 FFmpeg 是静态构建（无开发库可编译小程序），
MP4 的 tkhd 矩阵盒也不是简单补丁能改。

**获取方式**：用手机竖着拍一段视频（多数手机相机会写入 rotation=90），
或用有图形界面的工具（如 HandBrake、MP4Box）设置旋转后再导出。

**为什么必须验证**：`FfmpegCodecApi.cpp` 里已经实现了旋转检测与
90/180/270 度的 YUV420 平面旋转（`RotateYuv420`），但**从未在真机上验证过**。
未经测试的旋转逻辑有可能把画面转错方向 —— 那比不转更糟。
验证方法：设置页「抽帧自测」会报告输出尺寸，
旋转正确的话尺寸应当是互换的（如源 320x180 → 输出 180x320 比例）。
